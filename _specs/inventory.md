# Scope, decisions and research

MacPrintQueueView ("Mac Print Queue View") is a native macOS app that shows what is actually being printed from the existing macOS print queue: select a print job and see a preview of its content. The user can also manage their own jobs in the queue. Target environment: Apple Silicon Mac, macOS 27 (deployment target macOS 14), Xcode 27, Swift 6, printing system CUPS. Distribution: free through the Mac App Store.

## Product decisions

Explicit user decisions, all made on 2026-11-16: D1–D37 during the work recorded as phase 00, D38 and later in phase 01. Other choices in the specs are implementation defaults; the main ones are listed below and in the "Observed, yet to be confirmed" section of each feature.

| Decision | Agreement |
| --- | --- |
| D1 | Show the real, existing macOS print queue (not a virtual printer or a separate PDF viewer). Core flow: select a print job → view its content. Show printers and their queues, preview immediately, page through and zoom multi-page documents, update the queue when jobs appear or disappear, and clearly say when a preview is not available. Start simple; add nothing unnecessary. |
| D2 | A job deleted from the queue moves to the "Completed" list; that is accepted behaviour. |
| D3 | A completed job can be put back in the queue ("Print Again"). |
| D4 | The order of the queue can be changed (arrow buttons, context menu). |
| D5 | Completed jobs can be cleaned up (removed permanently). |
| D6 | Only the user's own jobs are shown; other users' jobs are not listed at all. |
| D7 | All text in the app, code comments and repository documents is in English (base language). |
| D8 | The source code is proprietary and kept in a private GitHub repository; the app is offered free of charge to everyone through the Mac App Store. License: "All rights reserved", Copyright Fenma IT. |
| D9 | Sign with the paid Apple Developer team FENMA IT B.V. (Team ID `8RQJ83KNF9`, account `developer@fenma.nl`). |

| D38 | Thumbnail zoom in the queue (RM-001; user, 2026-11-16, phase 01; the number of steps was extended from five to seven by D42): step 1 is the current thumbnail size (40 × 52 points) and the default; step *n* (1–5) is *n* times the size of step 1, so step 5 is 200 × 260 points. The "sheet of paper" keeps its fixed proportion; the row grows and the title and status stay beside the thumbnail. The controls are two buttons in the toolbar of the job column plus the shortcuts ⌥⌘= (larger) and ⌥⌘- (smaller); a button is disabled at step 5 or step 1. After trying the app, the user kept the buttons in the toolbar (2026-11-16). The chosen step is not remembered: every start begins at step 1. Only queued jobs have thumbnails (D14), so only the "In Queue" rows change. |
| D39 | Multiple selection in the queue (RM-003; user, 2026-11-16, phase 01): jobs in "In Queue" can be selected together with ⌘-click (and ⇧-click) and then moved, paused, resumed or canceled at once. Only queued jobs can be selected together; a completed job is always selected on its own. Preview of several jobs: a grid of equal blocks to the right of the list — 2 jobs side by side, 3–4 jobs 2 × 2, 5–9 jobs 3 × 3, 10–16 jobs 4 × 4; with more than 16 the first 16 in queue order are shown with a note on how many are not shown, while actions still apply to all selected jobs. Each block shows only the first page of the job. Canceling one job stays immediate (D18); canceling several asks for confirmation first. Moving a non-contiguous selection with the arrow buttons first gathers the selected jobs into one block at the first selected job and then moves the block one place (queue A B C D E with B and D selected, one step up → B D A C E). Dragging puts the selected jobs together at the drop position. |
| D40 | Reorder in the preview grid (RM-004; user, 2026-11-16, phase 01): when several jobs are selected, the blocks of the preview grid can be dragged to change the order, one block at a time. Workflow: select several rows → the grid shows them → arrange their order in the grid → then move the rows; the selected jobs move together as one block in the order arranged in the grid (D39). Confirmed by the user (2026-11-16): a drag in the grid changes the queue right away — the selected jobs keep the places they occupy together in the queue and are put on those places in the new grid order, other jobs stay where they are — so the grid always shows the queue order and a following block move keeps it. |
| D41 | Order numbers in the preview grid (user, 2026-11-16, phase 01): when several jobs are selected, every block of the grid shows its order number at the bottom right, counting left to right and then the next row. |
| D42 | Seven thumbnail steps (user, 2026-11-16, phase 01; extends D38, which had five): steps 6 and 7 are added (240 × 312 and 280 × 364 points). Implementation choices that follow from it: the job column keeps at least the thumbnail width plus 200 points for title, status and time, and widens when the user zooms in; if the columns then no longer fit, the window becomes wider (never beyond the screen; it is not narrowed again when zooming out). |
| D43 | Divider between the job list and the preview (RM-005; user, 2026-11-16, phase 01): thicker, so it is easy to grab when resizing the columns, and clearly visible. Implementation: the column dividers are 9 points wide instead of 1 (also the one at the printer column, as macOS applies one divider style per window), and the divider before the preview shows a line over the full height with a grip in the middle, in system colours for light and dark mode, drawn by a separate view on top of the divider that lets clicks through. (A first implementation replaced the class of AppKit's split view to draw the divider; that broke AppKit's toolbar observation and made the app crash when a row was clicked — reported by the user on 2026-11-16 and fixed before any review.) |
| D44 | A job that leaves the queue while it is selected (RM-007; user, 2026-11-16, phase 01) — printed, canceled or aborted — is deselected right away, so its preview disappears. A completed job that the user selects in "Completed" keeps its preview. (Until now the selection and preview stayed when the selected job finished.) |

## Implementation defaults (not explicit user decisions)

Recorded so they do not silently become product decisions: refresh interval of 2 seconds; printer naming, alphabetical sorting and fallback selection; hiding an empty "Completed" section; one main window that quits the app when closed; text layout of plain-text previews (A4, 10 pt monospaced); the "Completed" list shows 50 jobs ordered by job number (highest first); removing a completed job and "Clear…" ask for confirmation; a job that is printing cannot be reordered; "Print Again" from the toolbar or context menu prints without confirmation; the language choice takes effect after a restart; the project layout. The user may confirm or change these in the phase 00 review.
